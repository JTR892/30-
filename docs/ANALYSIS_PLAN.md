# 核心分析计划 v0.5（DRAFT，待数据审计）

> 本文件记录拟议分析结构，不是冻结实验协议。最终类别、数据划分、训练预算和指标须根据真实数据审计确定。v0.4二分类代码目前不支持本计划。

## 数据约定

- 观察单位暂定为一张焊缝区域X射线裁剪图像。
- 目标类别拟包含无缺陷与多个经专业定义、标注核验的缺陷类型。
- 单一缺陷类型图像为主多类别评价候选；多缺陷共存图像不强制转成单标签，纳入方式待审计后决定。
- 标注实例数不等于唯一图像数；需分别统计每类标注实例、唯一图像、单一缺陷图像、多缺陷图像和无缺陷图像。
- XML匹配、坐标、图像尺寸、类别字典、标注语义及冲突情况未核验前，不视为可靠标签。
- 尽可能追溯原始底片、焊口、项目和采集批次。同源图像尽量按来源组划分；来源缺失须披露，不得声称底片级或跨设备泛化。

## RQ1：多类别聚类表现

候选比较：
- Baseline：ResNet18 + SimCLR。
- Attention：相同骨干与训练流程，加入空间注意力分支。

两组尽量共享初始化、训练图像清单、增强、优化器和训练预算。若使用ImageNet监督预训练，需披露外部监督初始化。目标域类别标签不参与表征训练、模型选择、K-means拟合和样本簇分配。

K-means为候选算法。已知K主实验与未知K扩展实验必须区分；K值规则尚未确定。若采用已知类别数K，应明确这是已知K条件下的无监督聚类，不声称自动发现未知类别数。

## RQ2：训练规模与注意力影响

设置低、中、高三个训练数据规模，具体数量待数据审计。抽样规则需预先确定并保证模型间配对。是否按类别分层、是否按来源分组以及规模分母，待数据结构确认后写入冻结协议。

核心比较可考虑逐规模计算：
- Δ_s(r) = ARI_attention,s(r) - ARI_baseline,s(r)
- 规模交互对比可比较低规模与高规模的Δ差异。

具体公式、主要规模对比、重复种子数量和统计汇总均待协议冻结后确定。不得预先假定低样本规模下注意力收益更大。

## RQ3：特征几何与稳定性

候选事后分析：
- 归一化特征的类内/类间距离；
- kNN purity；
- K-means不同初始化的分配稳定性；
- 不同训练种子间分配一致性；
- 注意力区域与经核验XML标注区域的关联（仅在标注语义及坐标审计通过后）。

依赖真实标签的分析须在分析方案冻结后进行，不得反馈到模型选择。稳定性不等于语义正确；二维降维图仅作可视化。

## 多标签与指标边界

普通单标签ARI、AMI、NMI不能未经定义直接用于多标签共存图像。需先确定主评价样本资格（例如经核验的单一缺陷类型图像）或制定适用于多标签任务的评价方案。整体多类别指标与缺陷子集诊断应分别报告，避免无缺陷类别主导结果。

## 训练预算与解释限制

低、中、高规模的具体样本数、batch、optimizer steps/epochs、曝光次数、增强方案、输入分辨率和重复次数待真实图像预实验后确定。报告唯一图像数、图像曝光次数、训练时间、吞吐和峰值内存。固定steps与固定epochs回答的问题不同，不得把单一预算设计的结果夸大为纯粹样本数量因果效应。

## 代码与协议兼容性

当前`audit.py`和`split.py`只支持defect/no_defect，`protocol.py`强制v0.4及K=2。当前代码不可用于本v0.5多类别正式流程。须在类别字典、多标签规则、来源分组及数据契约明确后再改造并增加测试。

## 证据边界

当前没有真实数据审计、正式训练或聚类结果。研究贡献、模型有效性和注意力作用均为待检验问题。不得把计划写成发现，不得声称首次提出相关方法或跨来源泛化。
