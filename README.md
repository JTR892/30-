**暂定工作题目：不同训练样本规模下空间注意力对焊缝X射线图像多类别无监督聚类的影响。**

## 当前研究问题

1. 在目标域类别标签不参与表征训练和聚类拟合的条件下，加入空间注意力是否改变无缺陷图像与不同缺陷类型图像的聚类表现？
2. 空间注意力的相对影响是否随无标签训练样本规模（低、中、高）变化？
3. 聚类表现变化是否伴随特征几何或聚类稳定性的变化？

前两个问题为主研究问题，第三个问题为解释性分析。研究不预设空间注意力有效，也不声称提出新的注意力算法。

## 研究对象与数据边界

- **观察单位：**一张已裁剪的焊缝区域X射线图像；不等同于完整底片、焊口或单个缺陷实例。
- **拟研究类别：**无缺陷，以及多个经专业定义和标注核验的缺陷类型。最终类别名单和合并规则尚未确定。
- **多缺陷图像：**若同一图像存在多种缺陷，保留其多标签事实，不为方便计算单标签指标而强行归入某一类。是否纳入主实验，待数据审计后决定。
- **标注实例与图像数：**标注实例数不等于唯一图像数。每类独立图像数、单一缺陷图像数、多缺陷共存图像数和无缺陷图像数均待核验。
- **XML标注：**在图像匹配、坐标系、图像尺寸、类别字典、标注语义及冲突情况完成核验前，不将XML视为已验证标签或区域证据。
- **来源独立性：**优先调查原始底片、焊口、项目及采集批次等来源信息。同源裁剪图像应尽可能按来源组划分。来源映射缺失时须披露，不能据图像级划分声称底片级或跨设备泛化。

此前资料中出现的15,194张、39,547张及各类标注实例统计，具有不同的来源和统计口径，不能直接合并或视为当前研究的已核实样本量。后续以实际数据清单、审计报告和来源证据为准。

## 暂定方法框架

- **Baseline候选：**ResNet18 + SimCLR。
- **Attention候选：**相同骨干与训练流程，加入空间注意力分支。
- 两组尽量共享初始化、训练图像清单、增强策略、优化器和训练预算。
- 若采用ImageNet预训练，须披露其外部监督初始化；目标域缺陷类别标签不用于SimCLR表征训练、模型选择或K-means拟合。
- 空间注意力结构、插入层级、输入分辨率、增强策略及训练超参数均未冻结。真实图像预实验须检查缩放、裁剪和增强是否破坏细小缺陷信息。
- 低、中、高训练规模的具体数量待数据审计后确定。

## 聚类与评价框架（候选，尚未冻结）

- K-means为候选聚类算法，尚未最终选定。
- 若主实验采用已知类别数K，须明确属于已知K条件下的无监督聚类，不得声称模型自主发现未知类别数。若研究未知K，须另行预先规定不使用测试标签的选K规则。
- ARI为主要外部指标候选；AMI、NMI为辅助外部指标候选；Silhouette为内部指标候选。
- 多标签图像不能未经定义直接按普通单标签ARI/AMI/NMI处理。主实验单标签样本资格或多标签评价方案待审计后确定。
- 应分别报告整体多类别聚类结果，以及在同一聚类分配上对缺陷图像子集进行的细粒度诊断，避免无缺陷类别掩盖不同缺陷类型之间的混淆。
- 聚类簇与真实类别的对应关系仅用于聚类完成后的评价，不用于聚类拟合或模型选择。

## 数据审计优先事项

后续收到数据后，优先以只读方式核验：

1. 图像总数、可读数量、尺寸、位深、通道及异常文件；
2. 每个原始标签的标注实例数和唯一图像数；
3. 无缺陷、单一缺陷类型、多缺陷共存图像的数量；
4. 图像与XML的匹配率、坐标合法性、类别冲突和标注完整性；
5. 文件字节级重复、近重复及可识别的同源裁剪；
6. 项目、设备、曝光条件、原始底片或焊口来源覆盖；
7. 各候选类别的样本量、类别不平衡及来源覆盖情况；
8. 数据使用与发表权限。

类别合并规则须依据标注规范和无损检测专业定义确定，不能仅凭标签名称相似或预期聚类效果自动合并。

## 与v0.4代码的兼容性警告

当前仓库中的代码和配置仍属于v0.4二分类原型，**暂不支持v0.5多类别正式数据流程**：

- `src/weldstudy/audit.py` 的标签映射只接受 `defect` 和 `no_defect`；
- `src/weldstudy/split.py` 只接受这两个标签；
- `src/weldstudy/protocol.py` 强制v0.4及K=2，并包含v0.4专属来源分组限制；
- `config/protocol.json` 仍为v0.4二分类DRAFT配置。

因此，当前不要使用上述v0.4审计/划分脚本对多类别数据执行正式划分，也不要将v0.4配置作为v0.5实验放行依据。本次暂不修改Python代码、测试或配置，待真实数据结构、类别字典、多标签处理规则和来源分组策略明确后，再制定数据契约并同步改造代码。
